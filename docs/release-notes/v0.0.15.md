# Canary Engine `v0.0.15` — Release Notes

**Status:** released on `dev` as tag `v0.0.15` (2026-09-30).
**Scope source:** `docs/roadmap/v0.1.0-plan.md` (`v0.0.15` — networking)
**Nature of this release:** the engine becomes multiplayer-capable at
the replication layer. `v0.0.15` implements the smallest real
server-authoritative path that builds on project state — reusing the
versioned codecs and snapshot contracts `v0.0.14` establishes, plus the
authority, removal history, and ordering networking genuinely needs —
per [ADR 0027](../decisions/architecture-decision-records/0027-minimal-server-authoritative-replication.md)
(Accepted) and [`networking.md`](../architecture/networking.md#status-in-this-foundation).

## What `v0.0.15` is

- **Replication transport crate.** New crate `canary-net`:
  `engine/canary-net/src/transport.rs` (object-safe, leak-free
  `NetTransport` trait with no third-party types in public signatures;
  private `QuinnTransport` QUIC default with ALPN `canary-1`,
  DER-bytes constructors, and certificate pinning as a proof-only peer
  policy), `frame.rs` (length-prefix framing whose limit gate runs
  before any allocation), `envelope.rs` (`postcard` envelopes with no
  default features — trailing bytes rejected, SHA-256 checksum verified
  before the payload is trusted), `ids.rs` (version/identity/counter
  newtypes, including `SimTick` keeping wire sequence, simulation step,
  and scheduler tick apart), `limits.rs`/`error.rs` (bounds plus typed
  errors, disconnects, and retryable-vs-fatal vs resync-required
  policy), and `sequence.rs` (`SequenceGate` rejecting
  duplicate/reordered session sequences so a message is never applied
  twice).
- **Replication vocabulary.** `replication.rs` (canonical
  snapshots — sort-then-checksum bytes — plus sequenced deltas with
  base-sequence basing and validate-all-before-apply semantics),
  `mapping.rs` (`NetEntityMap`: stable server-scoped identity,
  tuple-keyed so slot recycling never aliases), entity-level opt-in via
  the `Replicated` marker (`engine/canary-ecs/src/replication.rs`)
  composed with type-level opt-in via `ReplicationRegistry`
  (a component replicates only when the entity carries the marker
  *and* its schema is registered), and `codec.rs` (per-schema payload
  codecs; unknown schemas fail as resync-required, never panic).
  Dirty-set computation stays in `canary-ecs` via
  `World::query_changed_since` — no parallel dirty-flag system.
  `Tick` gains only `get()`/`from_raw()` boundary accessors
  (`engine/canary-ecs/src/column.rs`).
- **Session path.** `handshake.rs` (typed `Hello`/`Welcome`/`Reject`
  with independent protocol, schema-manifest, game, and plugin/API
  checks — mismatch is a typed reject followed by close),
  `input.rs` (per-client ingress validation: ownership, sequence,
  bounds, action-schema plus exact action-version compatibility, input
  window — malformed input is a typed error with no state mutation and
  the connection stays alive), `session.rs` (`SessionTable` plus
  `ClientAck` per-client cursors, whole-record disconnect),
  `queue.rs` (bounded queues with explicit backpressure: ingress
  overflow disconnects the offender, egress overflow drops the oldest
  stale state the next delta supersedes), `policy.rs` (connection
  admission, idle deadlines, and temporary bans on a caller-supplied
  `u64` clock — no wall-clock reads), and `metrics.rs` (capped
  per-client rows, evicted on disconnect, so churn cannot grow
  memory).
- **Removal history and resync.** `tombstone.rs` (`TombstoneLog`:
  bounded retention, per-client cursors, ack-gated reclamation,
  drop→resync) closes the durable removal/destruction gap [R-33](../reviews/risk-register.md)
  names; `resync.rs` (`BaselineRetention`: a bounded ring of recent
  authoritative snapshots consulted with the session-surviving
  tombstone log) lets a reconnect — always a new session — replay its
  shared baseline plus retained tombstones when covered, else take a
  live full snapshot. Per-delta journal replay is deliberately not
  built: retained snapshots plus tombstones supersede it (rationale
  documented in `resync.rs`).
- **Proofs.** `QuinnTransport` pinning proven over a real QUIC
  connection (right pin round-trips an envelope, wrong pin refuses the
  handshake); `tests/session_roundtrip.rs` runs server and client as
  separate processes over real TLS/ALPN, exchanging snapshot, deltas,
  and frame-tagged input; `loopback.rs` (in-process transport with
  deterministic counter-based loss/duplication/reorder/latency fault
  injection) carries the resync end-to-end proof (drop mid-session,
  reconnect, incremental replay, live deltas after) and the 5-cell
  network-conditions matrix — clean, loss, duplication, reorder,
  latency — converging to server state every cell with no
  double-apply, each fault cell proving its fault fired.

## What this release deliberately is not

- **Not per-delta journal replay.** Retained snapshots plus the
  tombstone log supersede a journal; see `resync.rs` for the recorded
  rationale.
- **Not an unreliable datagram lane.** Needs measured
  latency/throughput evidence per ADR 0027 before it earns its place.
- **Not client prediction, reconciliation, or rollback.** The client
  renders what the server sends; convergence, not prediction.
- **Not production identity or matchmaking.** Certificate pinning is a
  proof-only peer policy; user identity, provisioning, accounts, and
  abuse prevention are not delivered here.
- **Not cross-build wire compatibility.** No compatibility is promised
  between incompatible schema manifests; version domains are checked
  independently and mismatches are typed rejects.
