# Canary Engine `v0.0.11` — Release Notes

**Status:** implemented on `dev`, not yet tagged — `harden then cut`;
this note records the release scope for the future tag, it does not
claim a release happened.
**Scope source:** `docs/roadmap/v0.0.11-roadmap.md`
**Nature of this release:** the first real simulation. `v0.0.11` gives
the engine 2D physics — bodies that fall, collide, and rest — driven
through the scheduler and drawn through the renderer, with the 3D
lineup (Jolt canonical, Rapier3D alternative, per ADR 0019)
explicitly deferred, not half-built.

## What `v0.0.11` is

`v0.0.11` is where Canary's worlds start moving on their own:

- **`canary-physics`: minimal components + leak-free trait.** An
  object-safe `PhysicsBackend` trait (no third-party types in public
  signatures — verified by `cargo doc`), minimal component cut
  (`RigidBody`, `Collider`, `Velocity`, `GravityScale`, `LockedAxes`,
  `ColliderMaterial`, `PhysicsConfig`), and a private Rapier2D
  0.35.3 backend selected by dimension+backend configuration, never
  hardcoded.
- **Fixed-timestep stepping with scheduler ordering.** A
  `PhysicsClock` accumulator plus `SimulationTime` (at most four
  `1/60` s steps per tick, leftover dropped by the spiral guard),
  frame time arriving as a `FrameDelta` resource through the
  existing `tick(dt)` seam with no `App` redesign, and
  first-position registration ahead of transform propagation and
  every render bake (proven fresh both directions, stale when
  reversed).
- **Physics game proof.** A ground, falling-box, and
  scripted-kinematic-platform scene drawn as z-pinned quads through
  the unchanged soup bake (zero RHI churn): headless tests in the
  normal suite plus `#[ignore]`-gated pixel tests with an
  unstepped-pipeline negative control.
- **Measured, not assumed.** Box2D 3.2.0 measured against in a
  throwaway harness (rapier faster 1.13–1.19x on the N-box pile)
  and not shipped; determinism scoped to single-machine
  repeatability, not cross-platform.
- **2D writes that respect 3D state.** Physics writes x/y
  translation plus z-rotation only, preserving z translation,
  off-axis rotation, and scale — pinned by dedicated preservation
  tests, since a 2D step must never corrupt the axis it doesn't own.

## What this release deliberately is not

- **Not joints, scene queries, or 3D.** No joint types, no
  raycast/sweep/overlap queries, no Jolt or Rapier3D backends —
  each with an owning future (3D lands post-`v0.1.0` per the plan).
- **Not a camera, input, or App redesign.** Bodies are drawn as
  flat quads through fixed camera constants; the kinematic body is
  scripted, not played; the fixed loop lives in a subsystem-owned
  schedule, not in `App`.
- **Not audio, UI, state, or networking.** `v0.0.12` audio is next
  and consumes the asset-loading primitive plus the real timed
  loop proven here.
- **Not a second physics backend.** The trait carries the
  dimension+backend config idea from day one so a second backend
  never requires an API break — but only Rapier2D exists.

## Try it

```sh
git clone <this repository>
cd canary
git checkout dev
cargo build --workspace
cargo test --workspace
cargo test -p canary-render-ecs -- --ignored  # needs a Vulkan ICD
```

See [`README.md`](../../README.md) for the full picture and
[`CONTRIBUTING.md`](../../CONTRIBUTING.md) to get involved.

## What's next: goals for `v0.0.12`

Per [`docs/roadmap/v0.1.0-plan.md`](../roadmap/v0.1.0-plan.md),
audio: a real backend (`rodio`, the standard pure-Rust choice)
behind Canary's own trait, with an `AudioSource` component
triggered by real game state playing real assets loaded via
`v0.0.10`.
