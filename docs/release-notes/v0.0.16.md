# Canary Engine `v0.0.16` — Release Notes

**Status:** cut on `dev` as tag `v0.0.16` (2026-10-01).
**Scope source:** `docs/roadmap/v0.1.0-plan.md` (`v0.0.16` — live collaboration)
**Nature of this release:** the engine gains its first shared-authored-state
slice. `v0.0.16` implements the server-authoritative operation path built
directly on `.14`'s stable IDs/codecs and `.15`'s versioned transport —
one authored-transform operation with server-assigned ordering,
permissions, conflict behavior, persistence, and reconnect recovery — per
[ADR 0028](../decisions/architecture-decision-records/0028-authoritative-live-collaboration-operations.md)
(Accepted) and
[`live-collaboration.md`](../architecture/live-collaboration.md#status-in-this-foundation).

## What `v0.0.16` is

- **Collaboration operation crate.** New crate `canary-collab`:
  `engine/canary-collab/src/op.rs` (the one operation — complete
  local-transform replacement on an existing authored entity — with
  `TransformPayload::validate`: finite floats, normalized quaternion
  within `QUAT_NORM_EPSILON`; zero/negative scale is content),
  `actor.rs` (server-minted `ActorId`, owner/editor/reader `Role`,
  `ClientOpId` bounded to 128 bytes), `error.rs` (typed rejects
  including `TooLarge`), `permissions.rs` (server-side
  `PermissionStore`: roles plus fencing epoch in its own atomic-JSON
  file, epoch 1 at provisioning, restart bumps the epoch, the file wins
  for known actors — provisioned out-of-protocol from pre-shared
  credentials), `wire.rs` (bounded `postcard` request/response/sync
  codecs plus the owned frame-tag registry: `TAG_EDIT`/`TAG_SYNC`,
  versioned with `COLLAB_PROTOCOL_VERSION`), and `session.rs` (the
  authoritative `Session` with fixed validation stages 1–11, durable
  commit before ack/broadcast, and an ordered FIFO broadcast outbox
  capped at 1024 messages).
- **Eleven validation stages.** Every submission runs the same fixed
  order: wire decode (1), protocol/schema compatibility (2),
  credential authentication (3) with idempotency beside it (3b: an
  identical `(actor, client-op-id)` replay returns the prior outcome;
  an evicted ID follows resync-or-reject, never silent re-execution),
  role permission (4), target existence plus target-scoped
  compare-and-set (5), numeric payload validation (6), the prefab veto
  (7), migration/codec rules over the `.14` vocabulary (8), durable
  commit (9: mutate a candidate, persist state plus history in one
  atomic write), swap-in with tail-eviction of idempotency entries
  (10), and accept plus ordered broadcast (11). No client-supplied
  identity is ever trusted; there is no global CAS, no LWW, and no
  history rewrite.
- **Revisions and history in `canary-state`.** `revisions.rs` adds
  `LogicalEntityId` (the validated `entity.<local>` suffix — a rename
  is delete-plus-create, never a silent retarget),
  `ProjectRevision`/`ObjectRevision`/`OperationSequence`, and the
  additive in-document `history` section (`DocumentHistory`: project
  revision, next sequence, per-target revisions, bounded retained tail,
  checkpoint, evicted count) riding the same canonical JSON and the
  same atomic save as the authored state it versions — one durable
  commit covers both. It is `#[serde(default)]` and skipped while
  empty, so files that never saw collaboration are byte-identical to
  pre-history files and genesis is project 0 / next-sequence 1
  regardless of the human log. `trim_retained` (bounded tail, default
  128) records a checkpoint envelope with every trim, and
  `tail_since`/`TailGap` gives a client behind the checkpoint the
  snapshot-plus-checkpoint path, never a partial tail. The machine
  history is the ordering truth: the accept path never calls
  `record_change` — no dual-write into the human `changes` log, an
  explicit ADR 0028 selection, not an omission.
- **Document gates.** `AuthoredDocument` grows the checks the session
  invokes: `entity_section_exists`,
  `transform_override_allowed` (the prefab veto, reusing the one-level
  prefab resolve/bake rules — prefab-free entities are editable, a
  prefab instance is vetoed when its reference is missing, malformed,
  unknown, chained, nested, or supplies a transform the instance never
  declared its own override for), and
  `entity_transform`/`set_entity_transform`.
- **Authoritative session host.** `engine/canary-runtime/src/collab_session.rs`
  composes `CollabSessionHost` over the `canary-net` framing: the
  session consumes decoded requests and emits ordered outcomes while
  the runtime moves the bytes. Server-assigned sequences stay
  monotonic across restarts via the durable store — the server reloads
  the last assigned sequence before accepting new ops and never reuses
  a sequence after restart (single-writer fencing with a
  restart-surviving order).
- **Ceilings with typed failures.** The limit gate runs before any
  allocation: 8 KiB requests, 512 B sync requests, 1 MiB responses and
  snapshots. Oversize fails typed (`CollabError::TooLarge` on the
  content gate, the encoded-reply gate, and every frame-body path),
  never truncated and never a generic `Malformed`. The 1 MiB snapshot
  ceiling is the `.16`-and-`.1.0` contract; the revisit trigger is the
  first real project whose canonical snapshot exceeds 512 KiB
  (chunked transfer wins over a silent bump). The accept path clones
  the whole document per operation — O(project bytes), fine for the
  small `.16` proof projects; the revisit trigger is p99 accept
  latency over 2 ms on a 1 MB project measured on real hardware.
- **Proofs.** Stage-gated unit coverage (each rejection stage pins its
  stable code) plus break-it suites
  (`canary-collab/tests/break_it.rs`,
  `canary-runtime/tests/collab_break.rs`): two clients converge
  through the session, duplicates/conflicts/denials behave per the
  written rules, restart fencing bumps the epoch with no sequence
  reuse or double apply, and reconnect resync recovers through the
  retained tail or a checkpointed snapshot.

## What this release deliberately is not

- **Not peer-to-peer authority or CRDT merge.** One session server
  sequences; conflicts resolve by target-scoped compare-and-set, and
  the loser resyncs or retries — never a merge.
- **Not offline operation queues.** A client behind the checkpoint
  takes the snapshot-plus-checkpoint path; there is no offline queue
  to drain.
- **Not generic patches or prefab-graph rewrites.** The edit surface
  is one operation on one authored object type; the prefab veto says
  no where the one-level rules say no.
- **Not editor UI, presence, cursors, or locks.** No UI exercises
  this path; a small client/API does.
- **Not hosted identity.** Roles are provisioned out-of-protocol from
  pre-shared credentials; there is no in-protocol grant/revoke in
  `.16`, and rotation/revocation are carried forward.
- **Not unbounded history or history rewriting.** The retained tail
  is bounded (128) with checkpoint envelopes; idempotency records
  live exactly as long as the retained window.
- **Not gameplay `World` replication.** This path versions authored
  project state only; change ticks and replicated gameplay state are
  not a collaboration history.
- **Not a hardened trust boundary.** Project and permission files are
  parsed with no depth/size budget (local, operator-owned input for
  now), and sync clients trust the session server without a
  signature (single-operator model for now) — both knowingly deferred
  with revisit conditions in `live-collaboration.md`, not overlooked.
- **Not per-property LWW.** Deferred, not rejected: finer-grained
  last-write-wins inside one accepted payload remains a possible
  future refinement inside the target revision check.
