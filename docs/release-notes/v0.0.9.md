# Canary Engine `v0.0.9` — Release Notes

**Status:** implemented on `dev`, not yet tagged — `harden then cut`;
this note records the release scope for the future tag, it does not
claim a release happened.
**Scope source:** `docs/roadmap/v0.0.9-roadmap.md`
**Nature of this release:** the foundation everything above it stands
on. `v0.0.9` has three parts in dependency order — a real-timed loop,
the spatial primitive, and rendering that draws real `World` state —
rather than any one subsystem in isolation.

## What `v0.0.9` is

`v0.0.9` is where Canary stops ticking in make-believe time, learns
where things are, and starts drawing what it knows:

- **A real-time loop.** `Subsystem::tick` takes a real delta-time, and
  `App::run` drives subsystems off the actual wall clock until the
  game says stop — alongside the deterministic fixed-`dt` `run_for`
  tests keep. Proven with sleep-based timing tests, not by reading
  the loop's own source back to itself.
- **`canary-transform`: the load-bearing primitive.**
  `Transform` (one always-3D `glam` representation for 2D and 3D —
  see ADR 0017, no split types), `GlobalTransform` (cached
  world-space matrix), and a `Parent`/`Children` hierarchy with a
  propagation system registered through `canary-scheduler` — the
  scheduler's first proof against a real gameplay-shaped system.
  Cycles fail loudly at write time; idle ticks mark nothing changed.
- **ECS-driven rendering.** The new `canary-render-ecs` bridge reads
  `GlobalTransform` + a minimal `Renderable` out of the `World`,
  CPU-bakes to screen space, and draws through the unchanged RHI
  with `hello_triangle`'s proven shader — zero new GPU API surface.
  Proven by real-pixel readback tests (distinct colors, moved-entity
  redraw, empty clear) running both locally on GPU hardware and in
  CI's dedicated integration job, and by `spinning-cube` rewritten
  on top of the bridge with its GIF output intact.
- **`glam` as the project's graphics math** (zero transitive deps),
  a macOS CI timing flake fixed by replacing a wall-clock assertion
  with a deterministic overlap proof, and an unused `wasmtime-wasi`
  dependency removed (lockfile shrinks accordingly).

## What this release deliberately is not

- **Not windowed presentation.** Everything asserted here is proven
  offscreen via pixel readback; a live screen arrives with `v0.0.13`'s
  interactive UI (see `v0.1.0-plan.md`), which is the first release
  that actually needs one.
- **Not RHI growth.** No textures, materials, depth, culling,
  uniforms, or buffer updates — the RHI is byte-for-byte its `v0.0.6`
  self; those are the named `v0.0.10` work package.
- **Not assets, physics, audio, UI, state, or networking.** Each has
  its sequenced release (`v0.0.10`–`v0.0.16`); none starts before its
  prerequisites, which is what this release just finished laying.
- **Not a camera, a mesh format, or an App-level scheduler.** Fixed
  constants, flat per-entity color, and one subsystem-owned
  `Schedule` are the honest placeholders, all documented as such.

## Try it

```sh
git clone <this repository>
cd canary
git checkout dev
cargo build --workspace
cargo test --workspace
cargo run -p spinning-cube -- /tmp/cube.gif
cargo test -p canary-render-ecs -- --ignored  # needs a Vulkan ICD
```

See [`README.md`](../../README.md) for the full picture and
[`CONTRIBUTING.md`](../../CONTRIBUTING.md) to get involved.

## What's next: goals for `v0.0.10`

Per [`docs/roadmap/v0.1.0-plan.md`](../roadmap/v0.1.0-plan.md),
minimal asset loading: `AssetId`/`AssetHandle<T>` plus one real mesh
loader and one real texture loader feeding the renderer `v0.0.9`
just wired up — real files from disk, not hardcoded arrays. Still
open and needing project-owner decisions: which mesh/texture
formats, `Handle` semantics (sync vs async, ECS component vs
resource), and whether `v0.0.10` loads sources directly or ships a
trivial cooked pass-through.
