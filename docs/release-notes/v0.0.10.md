# Canary Engine `v0.0.10` — Release Notes

**Status:** implemented on `dev`, not yet tagged — `harden then cut`;
this note records the release scope for the future tag, it does not
claim a release happened.
**Scope source:** `docs/roadmap/v0.0.10-roadmap.md`
**Nature of this release:** the loading primitive. `v0.0.10` gives the
engine real files from disk for the first time — one mesh format, one
texture format, and the identity/handle machinery everything file-fed
after this builds on.

## What `v0.0.10` is

`v0.0.10` is where hardcoded arrays stop being the only way to put
pixels and geometry on screen:

- **`canary-assets`: identity, handles, store, errors.** `AssetId`
  (opaque content hash of file bytes plus loader version, so loader
  fixes deterministically change IDs), `AssetHandle<T>`
  (generational index+generation mirroring `Entity`, stale resolves
  to `None`), `AssetStore<T>` (generational slots kept as an ECS
  resource), and `AssetError` (typed failures with path context).
- **GLB mesh and PNG texture loaders** — synchronous, path-based,
  with checked-in hash-stable fixtures and known-value assertions;
  corrupt, truncated, over-budget, and missing inputs fail with
  typed errors, never panics. Totality over hostile input is
  enforced (including a widened traversal guard after macOS CI
  caught a panic inside the `gltf` crate's own accessor walk that
  Linux never tripped on).
- **File-loaded meshes through the unchanged RHI** —
  `MeshRenderable` plus index-to-soup expansion at the bridge;
  `spinning-cube` loads its faces from `box.glb`, hardcoded arrays
  deleted.
- **Minimal texture creation and sampling** — purely additive RHI
  methods (`create_texture`, `create_textured_pipeline`,
  `set_texture`), UVs on the existing `Float32x2` attribute,
  single-texture fragment sampling with a Vulkan backend
  implementation; quadrant-correct pixel proof including a negative
  control that fails on the untextured pipeline.
- **`glam` 0.33, `x11rb` 0.14, wasmtime 48, naga 30** — the sandbox
  floor-pin era ended here: every rustc-1.75/1.91-era exact pin
  relaxed to caret requirements and the tree moved to latest viable,
  with the floor documented as history in `build-system.md`.

## What this release deliberately is not

- **Not cooking, cache, hot reload, or importers-as-plugins.**
  Loading is synchronous and path-based; the full `asset-system.md`
  pipeline (content-addressed cook, cache directory, filesystem
  watching, plugin importers) stays explicitly deferred with owning
  future releases — none of it partially implemented.
- **Not materials, depth, blending, or swapchain.** The texture
  slice is one RGBA8 image, one default sampler, one level; the
  general materials system and live window presentation wait for
  their own releases.
- **Not audio, physics, UI, state, or networking.** `v0.0.11`
  physics is next and consumes exactly the loading primitive and
  bridge paths built here.
- **Not a second mesh or texture format.** GLB + PNG prove the
  shape; format breadth is future importer work.

## Try it

```sh
git clone <this repository>
cd canary
git checkout dev
cargo build --workspace
cargo test --workspace
cargo run -p spinning-cube -- /tmp/cube.gif
cargo test -p canary-render-ecs -- --ignored  # needs a Vulkan ICD
```

See [`README.md`](../../README.md) for the full picture and
[`CONTRIBUTING.md`](../../CONTRIBUTING.md) to get involved.

## What's next: goals for `v0.0.11`

Per [`docs/roadmap/v0.1.0-plan.md`](../roadmap/v0.1.0-plan.md),
2D-first physics: a `PhysicsBackend` trait with a real Rapier2D
backend behind it, moving ECS `Transform`s from collider/rigidbody
components and drawn through the renderer `v0.0.9` wired up — plus
the fixed-step loop design the scheduler work anticipated.
