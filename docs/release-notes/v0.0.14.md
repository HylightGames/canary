# Canary Engine `v0.0.14` — Release Notes

**Status:** released on `dev` as tag `v0.0.14` (2026-09-29).
**Scope source:** `docs/roadmap/v0.1.0-plan.md` (`v0.0.14` — project state)
**Nature of this release:** the engine becomes saveable and restorable.
`v0.0.14` adds authored project state and deterministic simulation
snapshots as two separate products sharing one codec vocabulary —
canonical-JSON project documents with one-level prefab bake and staged
spawn, plus checksummed simulation snapshots with an owned-RNG
simulation step — per [ADR 0026](../decisions/architecture-decision-records/0026-authored-state-and-simulation-snapshot-contract.md)
(Accepted) and [`state-and-versioning.md`](../architecture/state-and-versioning.md#status-in-this-foundation).

## What `v0.0.14` is

- **Authored project documents.** `canary-state` reads and writes
  canonical pretty-JSON documents with deterministic ordering and
  unknown-field preservation (byte-identical load→save round trips),
  per-schema linear migration chains with a `migrate_fields` JSON
  bridge, an authored change log, atomic save (sibling temp file,
  flush, rename), and staged load.
- **One-level prefab bake.** `SpawnPlan::from_document` bakes `prefab`
  references one level — base fields first, the instance's own fields
  win per field, chained bases rejected — without touching a live
  world and without rewriting the document; bake output equals the
  hand-written equivalent.
- **Staged spawn.** `canary-runtime`'s `AuthoredSpawner` validates the
  whole plan (prefab bake, asset resolution, world registry agreement,
  full decode into staged typed inserts) before the first
  `World::spawn`, so any failure aborts with zero mutations.
- **Simulation snapshot boundary.** `SnapshotRegistry` captures only
  bound component/resource schemas in canonical record order
  (byte-identical across binding order and allocator history),
  `checksum` re-pins the envelope digest, and restore is staged
  validate-before-mutate — undeclared schemas, decode failures,
  dangling references, duplicate resource records, and tampered
  payloads all abort with zero world mutations.
- **Deterministic simulation step.** `Simulation::step` advances the
  ECS tick, folds `dt` into the sim clock (published as a `SimClock`
  resource), and draws from a seed-owned `OwnedRng` stream with no OS
  randomness anywhere. Tick, clock, and RNG position travel as a
  reserved `canary.sim-state` record with no wire-format break (the
  golden-bytes test still pins the pre-sim-state encoding); same-seed
  determinism holds across the save/restore boundary, step for step.
- **Presentation exclusion and recovery proof.** Presentation-only
  entities and unbound resources are never captured, never cleared,
  and survive restore untouched (sentinel tests plus byte scans of
  the capture payload). An interrupted authored save leaves the last
  good file loadable; a truncated final file fails typed at the
  parse gate (authored) or the checksum gate (snapshot) — never
  partial state.

## What this release deliberately is not

- **Not a `LogicalAssetId` registry.** Asset references resolve
  through a caller-supplied function (`$asset` markers,
  `StateError::AssetUnresolved` on miss); the stable registry stays
  future work.
- **Not nested prefabs or cross-history byte identity.** One level
  of prefab inheritance only; byte identity is claimed solely for
  identical declared state (same tick and RNG position).
- **Not transactional restore against impure decoders.** Restore
  purity is validate-all-plus-proof against the documented
  `SimComponent`/`SimResource` purity contract, not a transactional
  guarantee.
- **Not a wire-compatibility promise.** No compatibility is promised
  between incompatible schema manifests; wire compatibility is
  networking's concern (`.15`).
- **Not the removal/destruction log replication needs.** Durable
  removal records (R-33) are a `.15` item.
