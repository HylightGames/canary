past release, not a template file that should silently describe whichever

## 4. Verify formatting, linting, tests, and CI

- [x] `cargo build --workspace` — clean, zero warnings.
- [x] `cargo fmt --check` — clean (this sandbox now has `rustfmt`
  installed via `apt`, which `v0.0.1`'s session didn't have).
- [x] `cargo test --workspace` — 29 tests, all passing (3 `canary-core`,
  **19 `canary-ecs`** (up from 6, including two `proptest` property
  tests), 2 `canary-platform`, 3 `canary-plugin-api` unit + 2
  integration).
- [x] `cargo doc --workspace --no-deps` — clean; one
  `rustdoc::private_intra_doc_links` warning found and fixed during this
  session (a public doc comment linked to a `pub(crate)` trait method).
- [ ] **`clippy` was not runnable in this sandbox** — same limitation
  `v0.0.1`'s checklist flagged (no `apt` package, no `rustup` network
  access). Unlike `rustfmt`, no workaround was found this time either.
  CI is the actual gate for this and is the one item this session cannot
  close out itself; flagged honestly rather than assumed clean, exactly
  as the precedent set.

## 5. Remove dead code and unnecessary complexity

- [x] One `dead_code` warning (`TypedColumn::push`, an unused
  concrete-typed insertion path made redundant by the type-erased
  `push_any` every archetype transition already goes through) found
  during development and removed before this checklist was written, not
  left in.
- [x] No new dependencies added; `proptest`/`tempfile` were already
  present in `canary-ecs`'s `Cargo.toml` (added by a prior session in
  anticipation of this exact work) and `Cargo.lock` is unchanged.
- [x] Reviewed for premature abstraction: `World::type_id_for_schema`
  returns a bare `TypeId` rather than building a full type-erased
  insert/get-by-`TypeId` API that only a not-yet-built Tier A consumer
  would exercise — see ADR 0010's "Resolution" section for why that
  boundary was deliberate, not an oversight.

## 6. Identify anything that should be postponed to `v0.0.3` or later

Per [`v0.0.2-roadmap.md`](../roadmap/v0.0.2-roadmap.md)'s own scope: the
parallel job-stealing scheduler and the Tier A (WASM) consumer of the
component-identity registry. `docs/roadmap/status.md` already sequences
Tier A plugin loading as `v0.0.3`; that sequencing is under active
discussion (alongside broader architecture direction) as this checklist
is being written, and may be revised on the record before `v0.0.3` is
formally scoped — see [`RELEASE_NOTES_v0.0.2.md`](../../RELEASE_NOTES_v0.0.2.md#whats-next-goals-for-v003).
