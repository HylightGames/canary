# `v0.0.10` Roadmap: Minimal Asset Loading (`canary-assets`)

Single focus, per [`docs/roadmap/v0.1.0-plan.md`](v0.1.0-plan.md#v0010--minimal-asset-loading):
real files from disk feed the renderer `v0.0.9` built. Deliberately
minimal relative to [`docs/architecture/asset-system.md`](../architecture/asset-system.md)'s
full design (content-addressed cooking, importers-as-plugins, hot
reload) — those remain real, intended future work, not required for
`v0.1.0`'s bar. What's required: `AssetId`/`AssetHandle<T>` (the
runtime-facing API surface
[`docs/architecture/execution-model.md`](../architecture/execution-model.md)'s
own constraints leave open, content-addressing itself having been
decided already), and a real loader for at least one mesh format and
one texture format.

## Why this, and why bounded this way

`v0.0.9` closed its loop: a system queries `World` state and draws it.
But every vertex it draws is still a hardcoded Rust array
(`spinning-cube`'s `CUBE_CORNERS`/`FACES`) — no file has ever crossed
into the engine. `v0.1.0`'s bar ("assets feed the renderer and audio
system real files from disk, not hardcoded Rust arrays") fails
verbatim until that changes, and audio (`v0.0.12`) needs the same
loading primitive for sound files. So this release builds the loading
primitive once, against the renderer as its first consumer, rather
than letting audio or physics each invent file I/O separately.

Bounded by taking only the smallest slice that makes *file-loaded*
assets visible: synchronous loading (the scheduler has no
work-stealing pool and no concurrent-write story, so background
loading would guess at a threading API), direct source-file loads
(no cook step, no cache directory, no file watching), and exactly
two formats — GLB meshes, PNG textures. Each excluded piece names
its owning future: async/caching/hot-reload (later asset
milestones), importers-as-plugins (full `asset-system.md` design),
materials/depth/swapchain (the `v0.0.10` RHI package is textures-only
by the same minimal-slice rule; see below).

Checked before scoping: the three review triages and the risk
register. Adjacent but non-blocking: R-32/R-33 (change-detection
causality and removal signals for future replication of asset
handles — `v0.0.10`'s honest local answer is stale-handle→`None`,
not a tombstone mechanism) and R-16 (hot-reload serialization
contract — untouched; no hot reload here).

## Scope

- **New crate, `canary-assets`** (one-crate-per-subsystem rule),
  depending only on `canary-ecs` plus loading libraries — it knows
  nothing about `canary-render` or any backend; composition flows
  upward, preserving `canary-render`'s zero-dependency invariant.
- **`AssetId`**: own opaque type wrapping a content hash of (file
  bytes + loader version string). Baking the loader version into the
  hash input *is* `asset-system.md`'s "(source bytes + importer
  version)" rule in miniature: a loader fix deterministically changes
  IDs instead of silently serving stale bytes. Layout documented as
  provisional (version bumps change IDs by design).
- **`AssetHandle<T>`**: generational handle (`index + generation`,
  mirroring `Entity`'s proven shape) into an `AssetStore<T>`;
  stale-handle access returns `None`/typed error, never panics.
- **`AssetStore<T>`**: generational-slots container living as an ECS
  **resource**, keeping load/store logic unit-testable without a
  `World`.
- **`Mesh`**: positions + normals/UVs (loaded, stored, *unused by the
  renderer this release* — recorded as such) + indices, with
  load-time validation (index bounds, attribute-count consistency,
  triangle-mode only). Index→soup expansion happens at the bridge,
  not in the asset, keeping the asset honest for the day indices
  land.
- **`Texture`**: RGBA8-normalized (`width`/`height`/`rgba8`), all PNG
  color types converted, >8-bit downsampled (documented, not
  silent), with an enforced decode budget (`png::Limits` or explicit
  check) — over-budget is a typed error, untrusted-file discipline
  from day one.
- **GLB mesh loader + PNG texture loader**, synchronous and
  path-based, with committed fixtures (colored quad/box GLB, tiny
  RGBA PNG — generated once, checked in, hash-stable).
- **Renderer integration in two slices.** Meshes with zero RHI churn
  (`MeshRenderable` component, bridge expands indices to soup,
  existing bake/draw verbatim — file-bytes-to-pixels for geometry).
  Textures via a minimal, bounded RHI addition (texture creation,
  UV attribute on the existing `Float32x2`, single-texture fragment
  sampling in `canary-render` + `canary-render-vulkan`; bridge gains
  textured extract/bake/draw + a sampled test shader). Each addition
  documented as the minimal slice with the general system named as
  deferred.
- **`canary-loc` placeholder migration, if cheap**: rewire its loader
  closure onto the asset file-byte primitive per its own documented
  delete-and-replace contract — kept only if zero `canary-assets`
  API bending is needed, else explicitly deferred.
- Handle-design ADR ([ADR 0018](../decisions/architecture-decision-records/0018-asset-handles-and-synchronous-loading.md))
  landed before the implementation it records.

## Explicitly not in scope

- Async / background loading, filesystem watching / hot reload, a
  cache directory, cooked formats, `xtask cook` — later asset
  milestones, each named in `asset-system.md`, none partially
  implemented here.
- Importers-as-plugins — the full design's extension story; this
  release hardcodes exactly two loaders.
- Materials, depth testing, blending, buffer updates, swapchain /
  presentation — beyond the texture-only RHI slice; swapchain waits
  for `v0.0.13` per the recorded decision.
- Second mesh/texture formats, >8-bit-or-broader color pipelines,
  mipmaps, sRGB transfer-function handling beyond normalize-to-RGBA8.
- `xtask` asset subcommands — those arrive with the real pipeline,
  not the loading primitive.

## Verified, not assumed

- **All new pins verified by real build**, including transitives
  (`gltf`, `png`, hash crate): the ecosystem drifts between scoping
  and landing (windowing needed two passes), so pin verification
  happens at implementation time with rationale comments, per
  `build-system.md` policy — never trusted from `rust-version`
  fields alone.
- **Known-value fixtures, not "it loaded".** Quad positions/indices
  and PNG RGBA bytes asserted against checked-in values; corrupt /
  truncated / over-budget / missing fixtures proven to `Err`, never
  panic (negative controls).
- **No third-party types in any public signature**, checked via
  `cargo doc` — image/mesh library types stay inside function bodies
  and private modules (backend-trait hygiene, per coding standards).
- **Sampling proven live, not clear-color luck.** The texture
  quadrant test fails against the untextured pipeline by
  construction; moved-mesh redraw re-proves the
  propagation→extract→bake chain with file-loaded geometry.
- **`canary-render` still dependency-free** (`cargo tree` check);
  soup-path tests pass verbatim (no RHI regression).
- Full workspace `build`/`clippy -D warnings`/`test`/`fmt --check`
  clean, `cargo doc` zero warnings, `wasm32-wasip2` check, both
  `winit-backend` states, CI green including the extended
  integration job(s).
