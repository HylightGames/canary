# `v0.0.12` Roadmap: Audio Playback (`canary-audio`)

Single focus, per [`docs/roadmap/v0.1.0-plan.md`](v0.1.0-plan.md#v0012--audio):
an `AudioSource` component triggered by real game state, playing real
sound assets loaded via `v0.0.10`/`v0.0.11`'s asset pipeline, through
Canary's own trait. Deliberately minimal relative to
[`docs/architecture/audio.md`](../architecture/audio.md)'s full design
(custom in-house engine, DSP graph, buses, FMOD/Wwise bindings) — those
remain real, intended future work, not required for `v0.1.0`'s bar.
What's required: an `AudioBackend` trait (the solver seam game and
engine code program against, with no third-party types in public
signatures), one real backend behind it (rodio 0.22.x, explicitly
labeled bootstrap per
[ADR 0023](../decisions/architecture-decision-records/0023-audio-bootstrap-rodio-behind-custom-trait.md)),
and a tiny game-shaped scene proving a state change makes a sound.

## Why this, and why bounded this way

`v0.0.11` closed its loop: worlds move on their own. But they are
silent — no subsystem turns game state into sound, and `v0.1.0`'s bar
("audio plays real loaded sound assets, triggered by real game state")
fails verbatim until one does. So this release builds the audio
primitive once, against `Transform` (positional playback) and the
existing asset loaders as its consumers, rather than letting each
future game invent its own playback.

Bounded by taking only the smallest slice a "state change makes a
sound" scene needs: play/pause/stop/volume on named sources, distance
attenuation owned by Canary math (not the backend's spatial player),
and a fixed scheduler slot for the trigger system. Each excluded piece
names its owning future: DSP graph, buses, HRTF/Doppler, gapless music
(later audio milestones); FMOD/Wwise bindings (opt-in Tier B work);
streaming (asset milestone); custom in-house engine (post-`v0.1.0`
default per ADR 0023, replacing the private backend crate-side, never
the trait or components).

Checked before scoping: the review triages and the risk register, plus
ADR 0023's backend research (rodio alive at 0.22.x, Bevy-precedented;
kira heavier for zero bar-relevant gain; oddio stale; fundsp is DSP,
not playback; cpal-direct is the custom engine under another name).

## Scope

- **New crate, `canary-audio`** (one-crate-per-subsystem rule),
  depending on `canary-ecs`, `canary-scheduler`, and
  `canary-transform` plus `canary-assets` (`Sound`), `thiserror`, and
  `rodio` — it knows nothing about `canary-render`; composition flows
  upward through `canary-runtime`, preserving each leaf's dependency
  direction.
- **`AudioBackend` trait**: object-safe (`Box<dyn AudioBackend>`
  behind configuration, pinned by a compile-time dyn-compatibility
  test) and leak-free (sources cross as handles plus plain data;
  **no `rodio::`/`cpal::`/`symphonia::` types in any public
  signature** — rodio publicly re-exports cpal, so it must not be
  re-exported — rechecked via `cargo doc` plus grep). Methods:
  play/stop/pause/resume/set_volume on source handles, listener pose
  update, per-tick pump. Creation and pump failures are typed
  `AudioError`; a backend that cannot open a device degrades to a
  documented no-op rather than panicking (headless CI has no sound
  card).
- **Minimal components**: `AudioSource` (asset handle + trigger state:
  stopped/playing/paused + volume + loop flag), `AudioListener`
  (pose source for attenuation, defaults to origin-facing), and the
  `AudioConfig` resource (master volume plus backend selection,
  `backend = "rodio"`, `#[non_exhaustive]` so the custom engine
  arrives additively).
- **Private rodio backend** (`rodio = "=0.22.2"`, exact pin — it keeps
  a breaking cadence with an UPGRADE guide): `default-features =
  false` with only MIT/Apache-2.0 decoder features enabled
  (Symphonia is MPL-2.0 and stays opt-out, never default, per this
  engine's no-entanglement values); Canary-owned distance
  attenuation/pan math from `Transform` (rodio's `SpatialPlayer`
  has an open upstream bug with speed + looped decoders — own the
  small math instead of depending on it).
- **Trigger system**: a scheduler-registered system reading
  `AudioSource` trigger transitions plus game state and driving the
  backend (play on transition, stop on removal/despawn); ordering
  after gameplay writes, before/at the same point every tick —
  pinned both directions the way physics-first/propagation-first
  ordering is pinned.
- **Game proof**: a headless scene where a scripted game-state change
  (e.g. a body crossing a threshold, a timer firing) starts/stops a
  source loaded from the checked-in fixtures — asserted on backend
  call order and source state, not on audible output (CI has no
  ears); plus a decode-only test proving the pipeline feeds bytes
  without opening a device.
- **Version pin**: `rodio = "=0.22.2"` in
  `engine/canary-audio/Cargo.toml`, verified by a real build on this
  toolchain at implementation time, per `build-system.md` pin policy;
  `libasound2-dev` (or current equivalent) recorded as a Linux CI
  dependency alongside the existing Wayland/Vulkan ICD deps.

## Explicitly not in scope

- DSP graph, buses/mixing policy beyond per-source volume, HRTF,
  Doppler, gapless-music guarantees — later audio milestones, each
  named in the work plan, none partially implemented here.
- Streaming audio: sources are fully decoded `Sound` values; long
  streams arrive with the asset-streaming milestone, not here.
- FMOD/Wwise bindings: the trait is shaped so a Tier B binding does
  not fight mixer/bus/spatialization assumptions, but no binding
  ships in this crate.
- The custom in-house engine: retained as the long-term default per
  ADR 0023; it replaces the private backend, never the trait.
- WASM output proof: playback targets native devices in this
  release; the Tier A story for audio arrives with scripting needs.
- 3D positional subtleties past distance attenuation: no HRTF, no
  occlusion, no reverb zones.

## Verified, not assumed

- **Game-proof tests green**: scripted trigger starts/stops the right
  source (backend call order asserted against a stub backend, so the
  proof does not depend on real audio hardware); removal/despawn
  stops playback (no orphaned voices).
- **Known-state assertions, not "it played".** Source-state machine
  transitions pinned (stopped→playing→paused→stopped); volume and
  attenuation math asserted against hand-computed values; unknown
  source handles fail typed, never panic.
- **Negative controls throughout.** Missing device degrades to typed
  no-op; invalid sources `Err` with the offending value named;
  backend compiled without device access in the headless path.
- **No third-party types in any public signature**, checked via
  `cargo doc` plus grep over public signatures; `canary-audio`
  depends on `canary-assets`/`canary-ecs`/`canary-scheduler`/
  `canary-transform` only, plus `rodio`/`thiserror` — checked
  mechanically with `cargo tree`.
- Full workspace `build`/`clippy -D warnings`/`test`/`fmt --check`
  clean, `cargo doc` zero warnings, both `winit-backend` states,
  `wasm32-wasip2` check where applicable; CI green.
